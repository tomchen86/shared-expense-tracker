# Proposal：重建與第一個對外版本

- 日期：2026-10-23
- 狀態：Accepted <!-- 或：被 <檔案> 取代。合併之後只能改這一行。 -->

合併這份檔案，就代表整份被接受：除了「未決問題」，其他內容都已經決定。順序和時程寫在 `docs/roadmap.md`，不在這裡。

## 摘要

先把 baseline 手機 app 已經有的功能，一次一個 capability 搬進這個 repo，並補上 spec 和驗收測試。搬完之後加上帳號和雲端共享，做出第一個對外版本（手機 app）。之後的功能各自是一個階段，越遠的寫得越粗。

## 動機

讓情侶和小團體一起記帳、分攤支出。baseline 已經能在一支手機上記帳、分攤、分組、管理分類、看支出分析，但它沒有 spec，程式也依類型分散在各個資料夾，capability 對不到程式的邊界。先重建，之後每個新功能都能建立在 spec、測試和清楚的邊界上。

## 階段

### 重建

把 baseline（`/Users/tomchen/Codespace/shared-expense-tracker-baseline` 的 `1aceb68`）手機 app 已經做得到的功能搬過來：記帳和分攤、分組、分類管理、支出分析。一次搬一個 capability：規格作者對照 baseline 的程式和測試，寫 spec 和驗收測試；實作者只搬 spec 要求的部分（`AGENTS.md` 的 Migration）。baseline API 裡手機還沒用到的部分（註冊、登入、同步），留到需要它們的階段再搬。

驗證問題：v2 的手機 app 能不能取代 baseline？也就是 baseline 手機 app 做得到的事，v2 都做得到，而且每一條規則都有 spec 和通過的驗收測試。

### 帳號

註冊、登入、登出；登出或換手機之後，舊的登入立刻失效。資料一旦存在伺服器上，這是最基本的保護，所以排在雲端共享之前。baseline 的 API 已經有 email 註冊、登入和 refresh token，可以當參考；登出後讓舊的登入失效，以及手機上的登入畫面，是新做的。

驗證問題：使用者能不能在手機上註冊、登入、登出，而且登出或換手機之後，舊的登入立刻失效？

### 雲端共享

邀請伴侶或朋友加入同一個空間，各自在手機上記帳，連上線之後兩邊的資料一致，不遺失、不重複。先定好手機和 API 之間的資料約定，再接上同步。baseline 的 API 和手機都有同步的雛形，可以當參考。這個階段做完，就是第一個對外版本。

驗證問題：兩個人在各自的手機上離線記帳，連上線之後兩邊的資料是否一致，沒有遺失也沒有重複？

### 指定金額分攤

除了平均分攤和百分比，也能直接指定每個人出多少。

驗證問題：使用者能不能直接指定每個人出的金額，而且加總不等於支出金額時存不進去？

### 找得到以前的支出

搜尋、依日期篩選、排序。

驗證問題：有幾百筆支出時，使用者能不能很快找到想找的那一筆？

### 網頁版

在電腦上看帳和整理，資料來自雲端共享。

驗證問題：在網頁上整理過的資料，手機上看到的是不是一樣？

### 上線後的監控

同步衝突的統計、錯誤追蹤。

驗證問題：同步衝突和錯誤發生時，我們能不能在使用者回報之前就知道？

### 報表匯出

匯出成 CSV 或 PDF。

驗證問題：匯出的檔案能不能直接在試算表或 PDF 閱讀器裡打開，而且金額和 app 裡的一致？

## 原則

- 沒有網路也能記帳：任何階段都不能讓記帳需要網路，同步也不能讓手機上已經記下的資料遺失。

## 不做

- 在重建階段加新功能：重建的驗證問題是「能不能取代 baseline」，混進新功能就回答不了。
- 其他不做的項目，列在 `docs/roadmap.md` 的「不做」。

## 未決問題

- 重建時各 capability 的搬移順序：開始重建時，依 capability 之間的相依關係決定。
- 帳號要不要支援 Apple 和 Google 登入：baseline 的資料表預留了 email、Google、Apple 三種；取決於第一個對外版本要上架的平台的規定。
- 第一個對外版本上 iOS、Android，還是兩個都上：baseline 兩個平台都有各自的畫面元件。
- 同一筆支出在兩支手機上都被改過時，以哪一邊為準：雲端共享開始時決定。
