# Roadmap

這份文件只寫方向和順序：每個階段一行，寫它為什麼排在這裡；有 proposal 就連到它，階段開始之後再加上 milestone 的連結。細節寫在 `docs/proposals/`，進度和日期看 GitHub 的 milestone。只有方向改變時才改這份文件。

## 目標

為想簡單記錄日常支出、也要和伴侶或朋友一起管理開銷的人，做一個預設無須註冊、離線可用的記帳工具：個人和共同的支出記在同一個地方，不必分散記錄、事後反覆對帳。

記帳是基礎：資料存在自己的裝置上，共同帳本在連上線後同步，邀人加入也要容易。比價、收據辨識這類進階功能，需要時才開啟；長期要讓消費紀錄也能回答「這次買貴了嗎？」

## 現在（Now）

- **雲端共享**：邀請伴侶或朋友加入同一個空間，各自在手機上記帳，連上線後資料一致，不遺失、不重複。這是第一個對外版本的前提：沒有它，就只是一個人用的記帳 app。先定好手機和 API 之間的資料約定，再接同步。手動匯出入也在這個階段：把帳本匯出成檔案，也能從檔案匯入；預設免註冊、資料只在手機上，在雲端服務出來之前，換手機或手機壞掉時就靠它保住資料，換機碼也要沿用它的檔案格式。Milestone：[雲端共享](https://github.com/tomchen86/shared-expense-tracker/milestone/2)。Proposal：[雲端共享](proposals/2026-11-01-cloud-sharing.md)
- **找得到以前的支出**：支出清單一次看一個期間，可以搜尋、篩選、排序，清單上方的金額就是下面那些支出的總和。它全部在手機上完成，不必等雲端共享的 API，所以和雲端共享同時做。它會改掉 Expenses 頁列出全部支出的行為，趕在第一個對外版本之前改，已經在用的人才不會突然看不到舊的支出。Proposal：[找得到以前的支出](proposals/2026-11-19-find-past-expenses.md)

## 接下來（Next）

- **帳號**：可以選擇用 Apple 或 Google 登入；登入後原本的資料和共同帳本都還在，換手機後登入就能拿回共同帳本，也是之後訂閱的前提。要先有共同帳本，登入才有東西可以拿回，所以排在雲端共享之後。Proposal：[帳號](proposals/2026-11-01-accounts.md)
- **記錄還款**：成員把欠的錢還給對方之後，在群組裡記下這筆還款，雙方的淨額跟著調整，還清就歸零。少了它，對方轉帳之後淨額還停在原地，群組的結餘從此和實際對不上。還款和支出一樣要同步給其他成員，所以排在雲端共享之後；要同步就得改同步事件的格式，上架之後才改，還沒更新 App 的手機就看不到那個群組之後的變更，直到更新（ADR-0016），所以排在第一個對外版本之前。Proposal：[記錄還款](proposals/2026-11-18-repayments.md)
- **第一個對外版本**：手機 app 上架 App Store 和 Google Play，包括 App 名稱、圖示、隱私權政策和送審。要先做完雲端共享和帳號：這樣第一批使用者換手機或手機遺失時，就能登入拿回共同帳本。

## 之後（Later）

- **指定金額分攤**：除了平均分攤，也能依百分比分，或直接指定每個人出多少。這是很常見的分帳方式，但不影響第一個版本能不能上線。
- **網頁版**：在電腦上看帳和整理。要等雲端共享做好，網頁才有資料可以看。
- **上線後的監控**：同步衝突的統計、錯誤追蹤。要先有正式部署的 API 才有意義。
- **報表匯出**：匯出整理好、給人看的報表，例如 PDF。等有人真的需要把報表拿到別處用時再做。
- **雲端服務（訂閱）**：個人的多裝置同步、自動備份和恢復，用訂閱收費。要先確定有人持續在用，再開始收費。
- **Good Price**：商品搜尋、自選比較、單位價格、歷史價格，是可以開關的輕量功能。記帳要先好用，才有資料可以比價。Proposal：[Good Price](proposals/2026-10-29-good-price.md)
- **收據辨識**：OCR、品項拆解、候選商品、確認表格；比較大的模型和字典，開啟時才下載。要先有 Good Price 的商品和價格，辨識出來的品項才有地方對應。
- **Local AI**：處理規則解決不了的商品文字，是選配，不是必要的依賴。只有規則和字典不夠用、量測證明有幫助時才做。
- **家庭價格記憶**：把同一個共同帳本裡大家記的價格接成一條歷史，例如「你們家在這家店平均便宜 8%」。要先驗證比價本身有沒有用，跨人連結同一個商品也需要另外設計。

## 不做（Not doing）

- **連結銀行帳戶**：自動匯入交易要處理金融資料的法規和資安，超出這個專案能負擔的範圍。
- **即時匯率換算**：各幣別分開加總就夠用；換算會帶來「用哪一天的匯率」這種沒有標準答案的問題。
- **只為了換技術而重寫**：例如換狀態管理套件、換測試框架、上 Kubernetes。除非它解決一個量得出來的問題。
